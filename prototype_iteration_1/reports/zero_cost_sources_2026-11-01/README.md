# Zero-cost data-source investigation

November 1, 2026 (Toronto). Downloads and source receipts after midnight UTC are recorded as November 2 UTC. Budget: **$0**. No paid API, cloud instance, account creation, subscription or provider contact was used.

The useful new source is **CanCPLD historical cloud-to-ground lightning**, not a lightning climatology or forecast. A 2010 annual file and its grid-area file were downloaded and decoded, and a small area-weighted 10 km feature pilot was built. An additional archived HRDPS issue was also compared with the existing ERA5 reference at six pilot cell-times. These are source/feature validation results; no model was fitted, promoted or rescored on a final test.

## Current project baseline

The starting commit was `e17d1d5`, including the reported-fire/current weather workflow, 197 tests and 18 HTTP checks. Its captured feed has 9 reported fires, 12 historical reconstruction footprints and 21 local notices/drafts. It does not supply validated live perimeters or live forecasts.

The latest geographic wildfire-only reference and weather-history variants each find **2/92** positive cell-days at the fixed daily 1% review capacity. The history AP increase did not justify promotion. The latest feature study's 12 forward-fold fits and six refits, old final artifacts and model defaults are unchanged. The earlier 0/92 audit is a different study and is not the reference for this comparison.

The original live-qualification result remains **154,368 exact post-issue cell-time pairs from one run**, with no accepted grid/issue-time observed FWI state. The new six-pair source pilot uses a different, explicitly retrospective protocol and is not appended to that result or treated as live qualification.

## Existing caches inspected first

- Full historical terrain/weather panels and the old 31 protected scientific artifacts were already present.
- SCANFI v1.2 national files are 2020-vintage; the provincial selected-source SCANFI files are 2025-vintage. Existing FBP fuel maps are 2024/2026. They cannot silently become 2010–2019 predictors.
- Four full HRDPS manifests represent only **two distinct runs**: October 16 00 UTC (repeated builds) and November 1 18 UTC. A separate October 15 00 UTC cache initially contained only the one-hour lead, received after its valid time. Rebuilding the same run does not add independent weather cases.
- An existing hindsight ERA5 reference covers October 15–17 at 9,648 cells. It was reused without another CDS request. Existing daily station reports covered October 15–17, but lacked a complete reviewed state-to-grid lineage.
- Around 239 GiB was available at the initial storage check. New samples total approximately 96 MB of payload, including the weather pilot; no national raster set was downloaded again. Exact byte counts/hashes are in the manifests.

## Download and validation results

**Historical lightning:** 51,313,637-byte CG file plus 2,684,165-byte native cell-area file. The decoder reconciles GDAL band clocks with actual netCDF time bounds, preserves masked cells, verifies native coordinate/area units and aggregates density by intersection area with three existing 10 km cells near Red Lake, Thunder Bay and Timmins. It uses only complete intervals ending before the midnight Toronto issue; the resulting June 1–10 pilot has 30 cell-days, complete coverage and zero future-interval violations. All 24-hour pilot values are zero; eight seven-day rows are nonzero. The windows end one hour before these summer issues. This small geographic sample does not demonstrate model skill. Current ten-minute products were also zero over the tested Ontario bounding box; a bounding box is not the provincial boundary.

**Repeated weather:** 41,044,786 bytes, 15 GRIBs, October 15 00 UTC issue, three pilot cells, leads 18/19/20. The first lead initializes precipitation differencing; only leads 19 and 20 are compared. Six exact cell-time pairs with the existing ERA5 reference were valid for all four weather variables. MAE: temperature **0.557 °C**, humidity **2.922 percentage points**, wind **2.064 km/h**, precipitation **0.468 mm/hour**. This second issued run is a tiny hindsight source case, not a statistically independent qualification set; receipt occurred after the historical valid times. Original weather evidence remains unchanged.

**Station state candidates:** each downloaded day matched 110 Ontario records to station metadata. October 31 has 109 rows with finite FFMC/DMC/DC/location/timezone; November 1 has 108. Reported interpolation flags occur on 32 and 33 rows respectively, with non-success calculation statuses retained. The files supply candidate standard-noon clocks using station standard offsets and actual receipt timestamps. None is marked trusted or used as a model-grid seed. Station-to-grid transfer and interpretation remain unresolved, even though the November 1 report was received before the following Toronto midnight.

## API/user action needed

**Nothing is required from the user for the completed pilots.** No paid API or new key is needed for CanCPLD, recent HRDPS, CWFIS reports or the current lightning density product. New CDS reference downloads need a valid free CDS account/configuration and accepted dataset terms; existing configuration was not printed or copied. CaSPAr registration/Globus is only an optional route outside recent retention, and the portal must first become reachable. No external account was created.

Available tool/plugin capabilities were checked. Plugin Management searches for weather, geospatial and NASA returned no matching catalogue entries. That limited catalogue result does not establish that no weather plugin exists anywhere. No plugin was installed or permission changed; source APIs already covered the successful downloads.

## Next registered model step

Prioritize **past CG lightning density** before more weather-history variants: it introduces a measured ignition-related input absent from the historical classifier, while the latest extra weather-history features left fixed-capacity recall unchanged. This is a hypothesis supported by source suitability, not an achieved improvement.

Before fitting, acquire only development years needed by the frozen protocol, audit CG detection/reclassification changes, register source hashes/coverage, and lock area/time aggregation and two variants (24-hour density; 24-hour plus seven-day density). Keep physical observation time separate from unknown archive publication availability. Fit transforms on training partitions only; preserve all labels/split memberships, fixed 1% capacity and existing protected final periods. Use the existing forward folds and buffered geography, record uncertainty and calibration, and retain the simpler reference unless the registered development rule passes. Do not choose windows from the 92 exposed geographic positives. No such model comparison was run in this source-validation task.

For live qualification, collect independently issued fire-season forecast cases and later references with actual receipts and matching state lineage; 30+ issue dates is a planning target, not a validated sufficiency threshold. Recent Datamart archives can enlarge source diagnostics now; use a reviewed prospective AMQPS/manual capture protocol for actual issue-time evidence. Current station reports narrow access uncertainty but do not remove state-mapping or model-contract requirements. Spread still requires suitable current perimeters/times and prospective validation.

## Reproduce and review

From `github_iteration_1/prototype_iteration_1`, using the original full workspace:

```sh
../../.venv/bin/python -m scripts.lightning_pilot --workspace ../.. --archive ../../data/raw/zero_cost_sources_2026-11-01/cg_flashes_3hr_0.1-deg_2010.nc --area-file ../../data/raw/zero_cost_sources_2026-11-01/cell_area_0.1-deg.nc --output ../../reports/lightning_pilot_repeat
../../.venv/bin/python -m scripts.archive_weather_pilot --workspace ../.. --output ../../reports/weather_pilot_repeat
../../.venv/bin/python -m pytest tests team_repository/tests team_repository/capability_2_fire_spread/tests -q
```

Use a new output directory. The weather command is one ad hoc retrieval and can fail after archive retention expires; retain the pinned raw files and manifests. Its three cell IDs are taken from this task's original lightning pilot. The CanCPLD direct paths are recorded in `download_manifest.json`; no expensive netCDF package was added because existing GDAL/rasterio can decode them. A Git-only clone lacks full runtime/reference assets.

The new lightning tests cover midnight-crossing bins, missing intervals, unknown timezones, area weighting, zeros versus missing coverage and fractional-count rejection. See `regression_tests.txt`, `review_*.json` and `verification.json` for executed checks. Review is direct local/static review, not independent signoff. Existing frontend, live-readiness decision, benchmark values and Microsoft Project deferral are unchanged. Large raw samples remain local; Git contains code, compact pilot outputs, provenance and this report.

CanCPLD method reference: Cannon et al. (2025), [Scientific Data, DOI 10.1038/s41597-025-05924-7](https://www.nature.com/articles/s41597-025-05924-7).
